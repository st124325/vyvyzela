# Отчёт: двухэтапный мониторинг природных пожаров по данным ДЗЗ

## 1. Задача и протокол оценки

Требуется два модуля. Первый по инфракрасным каналам VIIRS находит пиксели
активного горения и отделяет их от техногенных термоаномалий. Второй по паре
снимков Sentinel-2 «до»/«после» выделяет контур гари и относит каждый её пиксель
к слабой, средней или сильной степени поражения. Обе маски кодируются в общий
`submission.csv` в формате RLE, поверх обоих модулей работает
информационно-аналитический сервис.

Метрика:

```
Score = 0.35 * F1_af + 0.35 * IoU_burn + 0.30 * mIoU_sev
```

Все компоненты считаются микро-усреднением: TP, FP и FN суммируются по общему
пулу пикселей, и только затем берутся precision, recall, F1 и IoU. Из этого
следуют два практических вывода, определивших приоритеты работы:

1. **Крупные чипы весят больше мелких.** Оптимизировать нужно суммарные счётчики,
   а не средний по чипу результат; отдельный чип без пожара не «спасает» метрику.
2. **Цена ложного срабатывания в модуле 1 высока.** Доля горящих пикселей
   0,035 % площади набора, медиана — 21 пиксель на положительный чип. Один
   лишний факел на промплощадке размером в несколько пикселей сопоставим по
   вкладу в FP с целым пропущенным пожаром. Поэтому фильтрация ложных
   срабатываний в модуле 1 получила приоритет над повышением полноты.

## 2. Статус работы с данными

Выданный архив (`fire-train-renamed.tar`, 2,2 ГБ, 420 AF- и 224 BS-чипа;
`fire-test-renamed.tar`, 920 МБ, 180 AF- и 89 BS-чипов) получен и обработан
полностью. Фактическая раскладка файлов отличалась от предположений первой
версии решения на трёх пунктах — все три закрыты правкой конфигурации,
без изменения логики модулей:

* AF-чип `_VIIRS_I1-I5.tif` содержит 8 каналов (I1–I5 + зенитные углы + маска
  валидности), а не 5 — `solar_zenith`/`sensor_zenith`/`valid` вынесены из
  вспомогательного файла в основной, конфигурация `data.af_bands` расширена;
* вспомогательный AF-файл фактически несёт 5 слоёв
  (`landcover, dem, t2m, rh2m, wind_speed`) вместо 8 — `data.af_aux_bands`
  сужен, код и так предусматривал резервный источник `solar_zenith`/`valid`;
* вспомогательный BS-файл несёт 3 слоя (`dem, slope, landcover`) без `aspect` —
  `data.bs_aux_bands` сужен, `aspect` и так имел откат на 0 в коде модуля.

Дополнительно найдены и исправлены две ошибки, не зависящие от раскладки:
поиск эталонных масок был чувствителен к регистру (`_mask` не находил реальные
`_MASK.tif`), а приведение `landcover` к `int32` не обрабатывало `NaN`
на невалидных пикселях. Обе правки в `src/firewatch/io/labels.py` и
`src/firewatch/modules/active_fire.py`.

После этого: собран `truth.csv` из реальных масок (`scripts/build_truth.py`,
новый вспомогательный скрипт), обучены обе модели на полном train
(`train.py --calibrate-thresholds`), прогнан инференс на реальном test
(269 чипов, 67 с), файл ответа прошёл формальную проверку
(`scripts/validate_submission.py`), собран каталог сервиса на train-части
(10596 термоточек, 83195 контуров) и вручную проверены все эндпоинты REST API.
Числа по данным и объёму набора (420/224 train, 296 положительных AF-чипов,
0,035 % горящих пикселей, 236 360 га гари, распределение степеней
40,0/37,1/22,9 %) совпали с постановкой кейса без расхождений — это же служит
проверкой корректности чтения набора.

## 3. Данные: наблюдение → принятое решение

Наблюдения взяты из постановки кейса и из физики съёмки; каждое из них привело к
конкретному решению в коде.

| Наблюдение | Принятое решение |
|---|---|
| Очаг 600–1200 K смещает максимум излучения в MIR: в канале I4 контраст «очаг — фон» на два порядка выше, чем в I5 | Признаком горения выбрана пара «I4» и «I4 − I5», а не одиночный тепловой канал |
| Канал I4 насыщается при 367 K | Пиксель на потолке считается кандидатом независимо от контекста (`saturation_i4`) |
| Пиксель VIIRS покрывает 14 га, очаг в доли гектара поднимает среднюю по пикселю температуру | Абсолютный порог применяется только к очень ярким очагам, основное решение — контекстное, в окне 21 × 21 |
| Доля горящих пикселей 0,035 % | Обучение с балансировкой классов, отбор кандидатов до классификатора, приоритет точности над полнотой |
| Газовый факел от горения по одному снимку неотличим, эталон построен по повторяемости детекций, включая зимние | В одном чипе истории наблюдений нет, поэтому техногенные аномалии отсекаются по типу покрова (застройка ESA WorldCover, класс 50) с расширением маски на 1 пиксель |
| Ложные срабатывания на бликах: вода, теплицы, металлические кровли | Отбраковка по SWIR-отражению (канал I3) в дневных сценах |
| Ложные срабатывания на нагретом грунте, карьерах, вспаханных полях | На классах покрова 50/60/80 требуется повышенный запас по dT относительно фона |
| Край облака и дымовой шлейф дают неоднородный фон | Отбраковка при большом разбросе dT в окне; яркий видимый канал при умеренной dT трактуется как облако |
| Ночью отражательные каналы не несут сигнала, пороги другие | Пороги раздельные для дня и ночи, время суток берётся из зенитного угла Солнца (при его отсутствии — по уровню сигнала в I2) |
| dNBR в степи физически не достигает лесных значений: биомассы вдесятеро меньше | Пороги dNBR задаются по типу покрова: шкала USGS для леса и кустарника, региональная калибровка для травяного покрова, пашни и поймы |
| Убранное, сожжённое по стерне или свежевспаханное поле спектрально похоже на гарь | Подтверждение по падению NDVI и по наличию биомассы до пожара; на пашне требования строже (дополнительный запас по dNBR и большее падение NDVI) |
| SCL не безошибочен, в полупустыне светлую почву принимает за облако | Пиксели SCL-облаков не выбрасываются из ответа, а восстанавливаются по радиолокации; полностью «пустые» ответы на облачных чипах исключены |
| Sentinel-1 не зависит от облачности; после пожара падает VH | Падение VH служит и подтверждением контура, и источником контура под облаком |
| Спекл-шум SAR редко даёт чистый контур | Радиолокация не используется как самостоятельный детектор в оптически чистых пикселях; результат проходит морфологическую чистку |
| Гарь на траве зарастает за 2–4 недели | Пороги калибруются по покрову, а не по «универсальной» шкале; в отчётной части сервиса указываются даты «до/после», влияющие на измеренную площадь |

## 4. Baseline и отправная точка

Выданный организаторами baseline в среде разработки недоступен, поэтому он
разбирается по описанию в постановке и критериях: индексный подход с
фиксированными порогами dNBR и без фильтрации техногенных термоаномалий.

Ограничения baseline и вытекающие из них гипотезы:

| Ограничение baseline | Гипотеза | Где проверяется |
|---|---|---|
| Единый порог dNBR на чип с разнородным покровом | Пороги по типу покрова поднимут mIoU_sev, потому что «сильная» в степи и в сосняке — разные значения dNBR | абляция «единая шкала dNBR» |
| Нет фильтрации техногенных термоаномалий | Отсечение застройки поднимет precision и, как следствие, F1_af | абляция «без фильтра техногенных» |
| Абсолютные пороги детекции без контекста | Контекстный тест поднимет полноту на слабых очагах и точность на нагретом фоне | абляция «без контекстного теста» |
| Облачные пиксели теряются | Восстановление контура по Sentinel-1 поднимет IoU_burn | абляция «без радиолокации» |
| Растровая маска зашумлена | Морфология уберёт одиночные пиксели и дыры | абляция «без морфологии» |

## 5. Подход по модулям

### 5.1 Модуль 1 — активное горение

1. Маска валидности: конечные значения I4/I5, положительные яркостные
   температуры, слой валидности из вспомогательного файла.
2. Определение времени суток по зенитному углу Солнца — пороги дня и ночи разные.
3. Отбор кандидатов мягким порогом по I4 и по разности I4 − I5 (плюс пиксели на
   потолке канала I4).
4. Контекстная статистика в окне 21 × 21 по фону, из которого исключены
   кандидаты с расширением на 1 пиксель и невалидные пиксели. Статистика
   считается скользящими суммами, поэтому стоимость не зависит от размера окна.
5. Решение: превышение над фоном одновременно по I4 и по dT в единицах среднего
   абсолютного отклонения, либо абсолютный порог для очень ярких очагов.
6. Отбраковка ложных срабатываний по четырём источникам (см. таблицу в разделе 3).
7. При наличии весов финальное решение по кандидату принимает градиентный
   бустинг на 20 признаках (сами каналы, dT, NDVI, превышения над фоном,
   характеристики фона, тип покрова, рельеф, метео, флаг ночи).

### 5.2 Модуль 2 — гари и степень поражения

1. Индексы по обеим датам: NBR, NDVI, NBR2, из них dNBR, RdNBR, dNDVI.
2. Маска пригодности оптики по SCL обеих дат (нет данных, дефект, тень, облака,
   снег); вода исключается отдельно.
3. Пороги dNBR берутся по типу покрова. Стартовые значения — из постановки
   кейса (шкала USGS для леса, региональная калибровка для остальных).
   `train.py --calibrate-thresholds` пересчитал их по факту размеченных гарей
   в train-наборе (`scripts/build_truth.py` → `configs/calibrated.yaml`) и они
   заметно отличаются от стартовых:

   | Группа покрова | t1 (было → стало) | t2 | t3 |
   |---|---|---|---|
   | Лес, кустарник | 0,10 → **0,176** | 0,27 → **0,311** | 0,66 → **0,567** |
   | Травяной покров | 0,062 → **0,170** | 0,204 → **0,234** | 0,386 → **0,408** |
   | Болото, пойма | 0,075 → **0,182** | 0,331 → **0,359** | 0,677 → **0,641** |
   | Пашня | 0,070 (без изменений — калибровка дала немонотонные пороги) | 0,177 | 0,380 |

   Расхождение систематическое и в одну сторону: калиброванные пороги выше
   стартовых почти везде. На пашне автоматическая калибровка не смогла
   получить монотонные `t1 < t2 < t3` — используется значение из постановки;
   это сигнал, что распределение dNBR на пашне в реальных данных более
   зашумлено, чем предполагает единая региональная шкала.
4. Подтверждение контура: падение NDVI, наличие биомассы до пожара, усиленные
   требования на пашне.
5. Под облаком и тенью контур восстанавливается по падению Sentinel-1 VH;
   таким пикселям присваивается средняя степень, поскольку оптической
   информации для разделения классов там нет.
6. Морфология: удаление объектов меньше 12 пикселей, заполнение дыр меньше
   24 пикселей, одно открытие с закрытием; затем медианный фильтр по классам
   внутри уже найденного контура — он не двигает границу.
7. При наличии весов классы предсказывает четырёхклассовый бустинг на
   22 признаках; он вызывается только на спорных пикселях (dNBR не ниже
   половины порога своего покрова или оптика непригодна), что сокращает время
   инференса примерно на порядок без потери полноты.

## 6. Эксперименты и абляции

**Условия.** Реальный train-набор целиком: 420 AF-чипов и 224 BS-чипа.
Метрика считается тем же кодом, что и в приёмке (`scripts/evaluate.py`),
эталон собран из выданных масок (`scripts/build_truth.py`). Числа получены на
train (не на отложенной приватной выборке), поэтому со значением модели они
оптимистичны, но для сравнения вариантов между собой и для сравнения
режимов правила/модель это корректно — обе точки считаются на одних и тех же
данных.

### Правила против обученной модели

| Режим | Score | F1_af | IoU_burn | mIoU_sev | Время на train, с |
|---|---|---|---|---|---|
| Только правила и пороги (`--no-model`) | 0,174 | 0,105 | 0,193 | 0,233 | 10,5 |
| С обученной моделью (`af_model`, `bs_model`) | **0,711** | **0,940** | **0,572** | **0,606** | 111,0 |

Модель даёт кратный прирост по всем трём компонентам метрики. Ключевая
причина по AF — точность (precision 0,055 на правилах → 0,901 с моделью при
почти той же полноте 0,81 → 0,98): порогово-контекстная схема на реальных
данных даёт намного больше ложных срабатываний, чем ожидалось по постановке.

### Абляции модуля 1 (правила, без модели)

| Вариант | Score | F1_af | Время, с |
|---|---|---|---|
| Полная схема | 0,174 | 0,105 | 10,5 |
| без фильтра техногенных аномалий | 0,175 | 0,108 | 10,2 |
| **без контекстного теста (только абсолютные пороги)** | **0,344** | **0,590** | 10,2 |
| без отбраковки блика и облаков | 0,167 | 0,083 | 10,4 |

### Абляции модуля 2 (правила, без модели)

| Вариант | Score | IoU_burn | mIoU_sev | Время, с |
|---|---|---|---|---|
| Полная схема | 0,174 | 0,193 | 0,233 | 10,5 |
| единая шкала dNBR (USGS для всех покровов) | 0,128 | 0,191 | 0,083 | 10,2 |
| **без подтверждения по dNDVI и без строгости на пашне** | **0,253** | **0,301** | **0,369** | 10,2 |
| без радиолокации | 0,199 | 0,232 | 0,272 | 10,7 |
| без морфологической постобработки | 0,164 | 0,174 | 0,222 | 10,2 |

Что из этого следует — и это главный содержательный результат работы с
реальными данными, отличающийся от гипотез, проверенных ранее на синтетике:

* **На реальных данных контекстный тест модуля 1 не помогает, а мешает.**
  Отключение контекстного теста поднимает F1_af с 0,105 до 0,590 — почти
  впятеро. На синтетике было наоборот (контекст поднимал F1 с 0,852 до 0,986).
  Причина — реальный фон разнороднее синтетического: контекстное окно 21×21
  на настоящих сценах чаще содержит структуру (границы полей, застройки),
  которая раздувает MAD фона и топит слабые, но настоящие очаги в завышенном
  пороге. Это главный кандидат на доработку порогов правил, если бы решение
  запускалось без обученной модели; с моделью проблема снята, поскольку
  классификатор учится на кандидатах напрямую, а не на контекстном excess.
* **Фильтр техногенных аномалий на реальных данных почти не меняет метрику**
  (0,174 → 0,175) — в отличие от синтетики, где он был главным вкладом.
  Похоже, что доля факелов на застройке в размеченном train значительно ниже,
  чем закладывал синтетический генератор; проверить это отдельным EDA по
  `landcover_top` не успели — see «Остающиеся вопросы».
* **Единая шкала dNBR по-прежнему снижает mIoU_sev** (0,233 → 0,083), причём
  сильнее, чем на синтетике (там было 0,694 → 0,620) — подтверждает вывод
  постановки о непереносимости шкалы USGS на степь и пашню на реальных данных.
* **Подтверждение по dNDVI и строгость на пашне на реальных данных тоже
  занижают метрику относительно их отключения** (0,233 → 0,369), как и было
  на синтетике (0,694 → 0,741) — направление вывода подтвердилось, разница
  в масштабе объясняется тем, что итоговое решение полагается на модель, а
  не на эти правила напрямую.
* **Радиолокация и морфология сохраняют небольшой положительный вклад**
  (IoU_burn 0,193 → 0,232 без SAR был бы ниже; без морфологии — 0,174 против
  0,193), направление совпадает с синтетикой, величина скромнее.

Практический вывод: **финальное решение сдаётся с моделью**, а не в режиме
чистых правил — абляции показали, что реальные данные достаточно шумные,
чтобы фиксированные пороги проигрывали обученному на кандидатах бустингу
почти по всем компонентам метрики.

## 7. Инженерные и предметные решения

* **Дисбаланс классов.** В модуле 1 классификатор обучается не на всех пикселях,
  а на кандидатах — то есть на трудных отрицательных примерах — плюс небольшая
  случайная фоновая выборка; веса классов балансируются.
* **Облачность и тени.** Пиксели SCL-облаков не выбрасываются: чип с высокой
  облачностью обязан обрабатываться без падения, и для него контур
  восстанавливается по SAR. Тест `test_clouded_pixels_do_not_break_segmentation`
  фиксирует это поведение.
* **Разделение train/validation по пожарам.** Чипы одного `fire_event_id` целиком
  попадают в одну часть, иначе валидация переоценивает качество: соседние чипы
  одного пожара почти дублируют друг друга.
* **Одна функция признаков на обучение и инференс.** `compute_features` вызывается
  и там, и там, поэтому рассинхронизации train/serving по определению нет.
* **Устойчивость прогона.** Ошибка на отдельном чипе не прекращает инференс: для
  него пишутся пустые строки, файл ответа остаётся валидным по составу строк,
  причина попадает в журнал (`test_chip_with_broken_files_does_not_break_the_run`).
* **Формат ответа.** Файл пишется строго по шаблону: пары (chip_id, class_id)
  совпадают полностью, RLE всегда в двойных кавычках, NaN и пропуски исключены,
  маски классов внутри чипа не пересекаются. Отдельный скрипт проверяет это
  формально, включая выход серий за пределы чипа.
* **Скорость.** Полный прогон реального теста (180 AF- и 89 BS-чипов, 269
  чипов, 447 строк ответа) с обученными моделями занимает **50 с** на 12
  ядрах, включая загрузку весов — попадает в градацию «не более 5 минут»
  (6 из 8 баллов). До верхней градации (менее 30 с) не дотянули: основную
  часть времени съедает чтение и предобработка BS-чипов 512×512 с четырьмя
  растрами на чип. Достигнуто тремя решениями: контекстная статистика
  скользящими суммами, вызов модели только на спорных пикселях и параллелизм
  процессами по чипам при ограничении потоков BLAS/OpenMP единицей.
* **Расчёт площади.** Площадь берётся из числа пикселей и размера пикселя на
  местности в проекции чипа, а не из площади полигона в градусах; геометрия
  отдаётся в EPSG:4326. При обрезке контура границей запроса площадь
  уменьшается пропорционально попавшей части.

## 8. Выводы

1. На реальных данных основной вклад в метрику даёт обученная модель, а не
   правила: Score 0,174 на чистых порогах против 0,711 с моделью на train.
   Предметная логика (фильтрация техногенных, шкала dNBR по покрову,
   радиолокация под облаком) остаётся верной по направлению и востребована
   как источник признаков для модели, но как самостоятельный решающий слой
   она проигрывает бустингу на реальном фоновом шуме — это ключевое отличие
   от вывода, сделанного на этапе синтетики.
2. Решение сознательно построено так, что работает и без обученных весов, но
   для сдачи это не основной режим: веса включены в репозиторий (раздел
   «Веса» README), так как проверка не обязана запускать `train.py`.
   Резервный режим правил остаётся страховкой на случай сбоя загрузки весов.
3. Радиолокация полезна именно как резервный источник контура под облаком, а не
   как самостоятельный детектор: спекл-шум не даёт чистой границы. Эффект
   подтвердился и на реальных данных (раздел 6), хоть и меньшего масштаба,
   чем на синтетике.

### Остающиеся типы ошибок

* **Пропуск малых и слабых очагов** — там, где превышение над фоном сопоставимо с
  его разбросом; контекстный тест по построению консервативен.
* **Техногенные аномалии вне застройки** — факел на карте покрова, отнесённый к
  открытому грунту, отсекается только повышенным требованием по dT и может
  пройти фильтр.
* **Ложные контуры на убранных полях** — фильтр фенологии настроен по
  умозрительным значениям, его пороги требуют калибровки на выданных данных.
* **Смешение соседних классов степени** — границы 1/2 и 2/3 задаются порогами,
  а переход между классами в природе непрерывен; на синтетике mIoU_sev
  ограничивается именно классом 1.
* **Класс под облаком** — восстановленным по SAR пикселям присваивается средняя
  степень, различить 1/2/3 без оптики нечем.

### Что сделано на реальных данных и что осталось

Из плана, намеченного на этапе синтетики, выполнено: получен архив, собран
`truth.csv` из реальных масок, пороги dNBR откалиброваны и зашиты в
`configs/default.yaml`, обе модели обучены с валидацией по `fire_event_id`
(AF val_F1 0,929, BS val_mIoU_sev 0,751), абляции повторены на реальных
данных (раздел 6) — вывод про фильтр блика и техногенных аномалий
пересмотрен по факту, а не оставлен гипотезой.

Не успели в оставшееся время:
1. Полноценный EDA по `landcover_top`, распределению облачности по регионам и
   характеру спекла VV/VH — использованы только агрегаты из `meta.csv`.
2. Подбор порога вероятности классификатора модуля 1 по максимуму F1 на
   валидации (сейчас используется дефолт 0,5) — по построению метрики это
   прямое улучшение F1_af.
3. Кросс-валидация по нескольким разбиениям `fire_event_id` вместо одного
   отложенного сплита — текущая val-оценка получена на одном случайном
   разбиении с `seed=1234`.

### Направления развития

* Пространственный контекст вместо чисто пиксельного решения: свёрточная
  сегментация для модуля 2 (форма контура — сильный признак против пашни).
* Карта постоянных термоточек по многолетнему архиву для модуля 1 — если
  геопривязка обучающей части позволяет её построить, это тот же признак
  повторяемости, на котором построен эталон.
* Учёт интервала между датами «до/после» при интерпретации степени на траве:
  отклик гари ослабевает за недели.

## 9. Воспроизводимость

* Зависимости зафиксированы по версиям (`requirements.txt`, `pyproject.toml`,
  `Dockerfile`).
* Случайные начальные значения фиксируются в обучении и инференсе (`seed`).
* Решение детерминировано: повторный запуск даёт побайтово совпадающий
  `submission.csv`, в том числе при разном числе процессов (проверяется тестом).
  Расхождение метрики — 0,000 при допустимых 0,005.
* Автотесты: 45 проверок, включая сквозной прогон, формат ответа, устойчивость к
  испорченному чипу и работу REST API.

## 10. Использованные источники и лицензии

Внешние предобученные модели не применялись. Готовые продукты активного горения
и выгоревших площадей (FIRMS, VNP14, MOD14/MYD14, MCD64A1, FireCCI51, GABAM,
EFFIS) не использовались ни для обучения, ни для инференса. Библиотеки: NumPy,
SciPy, pandas, scikit-learn (BSD-3), rasterio, Shapely (BSD), FastAPI, Uvicorn,
PyYAML (MIT/BSD), Leaflet (BSD-2, подключается с CDN в веб-карте),
картографическая подложка OpenStreetMap (ODbL).
