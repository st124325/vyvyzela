# План защиты (10 слайдов)

Регламент — короткое выступление плюс вопросы. Каждый слайд ниже описан как
«что показываем» и «что говорим»; цифры берутся из `docs/REPORT.md` и
пересчитываются после прогона на выданных данных.

## 1. Задача за 30 секунд
* **Показываем:** два модуля, общий `submission.csv`, сервис поверх обоих.
* **Говорим:** первый модуль отделяет природное горение от факелов и промплощадок,
  второй по паре «до/после» даёт контур гари и три степени поражения.

## 2. Почему это нельзя решить одним порогом
* **Показываем:** два графика — спектр очага против фона (I4 против I5) и шкалы
  dNBR для леса и для степи.
* **Говорим:** очаг в 3,6 % площади пикселя поднимает I4 на 237 K, а I5 — на 52 K;
  в степи биомассы вдесятеро меньше, и лесные пороги dNBR там недостижимы.

## 3. Схема решения
* **Показываем:** схему пайплайна из README (кандидаты → контекст → отбраковка →
  маска; индексы → пороги по покрову → подтверждение → SAR → морфология).
* **Говорим:** где проходит граница между правилами и обученной моделью и почему
  решение работает даже без весов.

## 4. Модуль 1: четыре источника ложных срабатываний
* **Показываем:** таблицу «источник → признак → как отсекаем».
* **Говорим:** факел от огня по одному снимку неотличим — отделяем по типу
  покрова; блик — по SWIR; вода — по NDVI; край облака — по разбросу фона.

## 5. Модуль 2: пороги, привязанные к покрову
* **Показываем:** шкалы 0,10/0,27/0,66 для леса против 0,062/0,204/0,386 для травы.
* **Говорим:** «сильная» в степи означает полное выгорание травостоя, а не то же
  самое, что в сосняке.

## 6. Облака, дым и пашня
* **Показываем:** чип с облаком: оптика, SAR, итоговый контур.
* **Говорим:** SCL-облака не выбрасываем, а восстанавливаем контур по падению VH;
  на пашне требуем дополнительный запас, иначе убранное поле становится «гарью».

## 7. Абляции: что именно дало прирост
* **Показываем:** таблицу из раздела 6 отчёта.
* **Говорим:** фильтр техногенных — главный вклад в F1_af (0,73 → 0,99),
  шкала по покрову — в mIoU_sev (0,62 → 0,69), SAR — в IoU_burn (0,81 → 0,87).

## 8. Результаты и скорость
* **Показываем:** Score и его компоненты, время инференса.
* **Говорим:** 180 AF- и 89 BS-чипов за 4,8 с на четырёх ядрах в режиме правил,
  21 с с моделями; параллелизм процессами, модель вызывается только на спорных
  пикселях.

## 9. Демонстрация сервиса
* **Показываем вживую:** выбор прямоугольника на карте, период, запрос; карта
  термоточек и контуров, выгрузка GeoJSON, справка по площадям; тот же результат
  через `curl` к `/api/query`.
* **Говорим:** площадь считается по пикселям в проекции чипа, контуры выгружаются
  в EPSG:4326 с атрибутами `contour_id`, `severity_class`, `area_ha`.

## 10. Ограничения и развитие
* **Показываем:** список остающихся ошибок из отчёта.
* **Говорим:** пропуск малых очагов, факелы вне застройки, границы между
  соседними классами; дальше — пространственный контекст вместо пиксельного
  решения и карта постоянных термоточек по архиву.

## Заготовки ответов на вопросы

* **Почему не нейросеть?** Доля горящих пикселей 0,035 %, чипов мало, а метрика
  микро-усреднённая: предметная фильтрация даёт больший прирост, чем ёмкость
  модели, и укладывается в верхнюю градацию по скорости. Архитектура допускает
  подстановку сегментационной модели — интерфейс модулей один.
* **Как отделяете факел от пожара?** По одному снимку — никак, он действительно
  горит. Используем внешний признак: тип покрова (застройка) с расширением маски;
  в эталоне кейса тот же смысл несёт повторяемость детекций по архиву.
* **Почему пиксели под облаком не выбрасываются?** Чипы с высокой облачностью
  входят в оценку. Мы восстанавливаем контур по Sentinel-1 и присваиваем среднюю
  степень, потому что различить 1/2/3 без оптики нечем.
* **Насколько устойчивы пороги?** Абляция показывает, что результат не меняется в
  диапазоне значений фильтра фенологии 0,08–0,12; калибровку по выданным данным
  выполняет `train.py --calibrate-thresholds`.
