# Автономное управление спутниковой группировкой

КосмоХакатон 2026. Веб-сервис планирует работу группировки на пятиминутных
шагах: распределяет задания (downlink/relay) между аппаратами с учётом
энергии, температуры, калибровки и лимита наземной связи, реагирует на
новые сообщения (задания, отказы, отмены сеансов) и умеет сравнивать два
варианта продолжения из одного состояния.

## Структура репозитория

```
model/        готовая расчётная библиотека кейса (не изменялась) — физика,
               допуск действий, Session/Environment. См. docs/*.pdf.
planner/      наш планировщик: greedy.py (scoring + baseline), run.py
service/      FastAPI: сессии, шаги, события, цели, сравнение, экспорт
web/          фронтенд без сборки: index.html + app.js + style.css
data/         сценарии кейса (P01–P04)
examples/     events_demo.json + saved_runs/ (примеры полных расчётов)
experiments/  сравнение baseline/scoring, скрипт сохранения примеров
tests/        pytest: формулы модели, планировщик, HTTP API
docs/         постановка/критерии/описание данных (PDF) + REPORT.md
```

## Требования

- Python 3.10+ (разработано и проверено на 3.12).
- Никакого внешнего фронтенд-тулчейна: `web/` — чистые HTML/CSS/JS, без
  CDN и сборки, работает офлайн.

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt   # рантайм + pytest/httpx
```

(`requirements.txt` — только рантайм-зависимости, без dev-инструментов.)

## Запуск сервиса

```bash
.venv/bin/uvicorn service.app:app --port 8000
```

Откройте `http://127.0.0.1:8000` — сервис отдаёт и API (`/api/...`), и
интерфейс (`/`) одним процессом. Сценарий работы оператора:

1. Выбрать сценарий (`P01`–`P04`), цель управления и алгоритм, при
   необходимости — изменить заряд аппарата/солнечную мощность/приоритет
   задания до запуска.
2. Считать пошагово, N шагов вперёд или до указанного шага.
3. На любой границе шага отправить сообщение (новые задания, недоступность
   аппарата, отмена сеанса) или сменить цель управления.
4. Кликнуть по любому заданию — открывается разбор по шагам: кто и что
   делал среди допустимых исполнителей, почему запрошенное действие
   отклонялось.
5. Нажать «Проанализировать потери» — сервис раскладывает просроченные
   задания на жёсткие ограничения задачи (не было сеанса связи — планировщик
   не мог помочь) и потери, на которые планировщик влияет (конкуренция за
   ресурс, энергия, приоритет), плюс сводку отклонённых команд и простоя.
6. Форкнуть текущее состояние в ветвь сравнения с другими
   целью/алгоритмом, досчитать обе и увидеть разницу и вердикт.
7. Выгрузить результат — файл по схеме `cosmo-B-ops-result-1.0`.

## Тесты

```bash
.venv/bin/pytest tests/ -v
```

Покрытие: формулы энергии/температуры и допуска действий сверены с
формулами и примерами из `docs/03_Описание_данных` (`test_resource_env.py`);
сквозной прогон обоих планировщиков (`test_planner.py`); полный жизненный
цикл HTTP API — создание, шаги, событие, форк, сравнение, экспорт, коды
ошибок (`test_service.py`).

## Эксперименты и метод

`docs/REPORT.md` — описание планировщика и разбор результатов. Чтобы
воспроизвести сравнение baseline/scoring на всех сценариях:

```bash
.venv/bin/python experiments/compare_strategies.py   # -> experiments/results.json
```

## Примеры сохранённых расчётов

`examples/saved_runs/` содержит полные экспорты (`Session.result()`):
ознакомительная смена целиком и суточная смена с применёнными событиями.
Пересчитать и сверить с сохранённым файлом:

```bash
.venv/bin/python model/operations.py --result examples/saved_runs/P01_priority_scoring.json \
    --output /tmp/replay.json
python3 -c "import json; a=json.load(open('examples/saved_runs/P01_priority_scoring.json')); \
    b=json.load(open('/tmp/replay.json')); print(a['summary']==b['summary'])"
```

## API (кратко)

| Метод и путь | Назначение |
|---|---|
| `GET /api/scenarios` | список сценариев с метаданными |
| `POST /api/sessions` | создать смену (`scenario`, `goal`, `algorithm`, `overrides`) |
| `POST /api/sessions/{id}/advance` | шаг / N шагов / до шага (`steps` или `until_step`) |
| `POST /api/sessions/{id}/event` | сообщение (`add_jobs`/`satellite_outage`/`close_downlink`) |
| `POST /api/sessions/{id}/goal` | сменить цель управления на текущем шаге |
| `POST /api/sessions/{id}/fork` | ветвь сравнения из текущего состояния |
| `GET /api/sessions/{a}/compare/{b}` | различия и вердикт (только для общей ветви) |
| `GET /api/sessions/{id}/jobs/{job_id}/explain` | история задания по допустимым исполнителям |
| `GET /api/sessions/{id}/diagnostics` | потери и узкие места: жёсткие ограничения задачи vs влияние планировщика |
| `GET /api/sessions/{id}/export` | полный результат смены (`cosmo-B-ops-result-1.0`) |

## Версия алгоритма

`run_metadata` каждой смены содержит `algorithm` (`scoring-greedy` или
`baseline-edf`), `goal` и `version`; при смене цели на ходу — журнал
переключений; при сравнении — `root_id`/`fork_step` ветви-источника.
