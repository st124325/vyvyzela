# Проектирование устойчивой спутниковой группировки

Веб-сервис для проектирования спутниковой группировки (48 КА, орбиты 550 км, 3 очереди
запуска) и оценки доступности связи северных наземных пунктов со шлюзом выхода в наземную
сеть. Позволяет менять конфигурацию, моделировать покрытие и МСС-сеть, строить маршруты
до шлюза с учётом отказов и сравнивать сохранённые варианты.

## Запуск

Приложение полностью статическое (HTML/CSS/vanilla JS), без сборки и без backend.

```bash
# любой статический сервер, например:
python3 -m http.server 8080
# затем открыть http://localhost:8080/index.html
```

Двойным щелчком по `index.html` тоже можно открыть напрямую в браузере (`file://`) — всё,
кроме загрузки примеров через кнопку «Browse» на самой странице, будет работать одинаково.
Загрузка сценария через форму (`<input type=file>`) работает и без сервера.

Зависимостей и `npm install` не требуется.

## Структура репозитория

```
index.html            — разметка и подключение скриптов
styles.css             — стили
js/geometry.js         — орбитальная механика: положения спутников, видимость, затенение Землёй
js/routing.js          — маршрутизация (Дейкстра по графу МСС) и причины отсутствия маршрута
js/simulation.js       — модель данных, состояние сети на шаг времени, суточная симуляция,
                          доп. функции (поиск уязвимых спутников, автоподбор конфигурации)
js/validate.js         — валидация загружаемого файла сценария
js/app.js              — UI: форма конфигурации, карта, таймлайн, Гант, сравнение вариантов
tests/smoke.html        — смоук-тесты расчётных модулей, открывается прямо в браузере
tools/tune.py           — независимый Python-повтор физики, использовался для подбора
                          рекомендованной конфигурации (офлайн, не часть веб-сервиса)
examples/               — сгенерированные локально JSON-сценарии для проверки загрузки
                          (не официальные данные кейса — см. раздел ниже)
```

## Как проверить, что расчёты не сломаны

Открыть `tests/smoke.html` в браузере — страница сама запускает проверки геометрии,
маршрутизации, симуляции и валидации и показывает счётчик «пройдено/провалено» внизу.
Отдельного тест-раннера не требуется.

## Ограничение: нет официальных входных данных кейса

В момент разработки в проекте не было файлов `geometry.py` и официальных сценариев
(`01_full_constellation.json` и др.), упомянутых в постановке задачи. Вся орбитальная физика
(`js/geometry.js`) реализована самостоятельно по формулам невозмущённого кругового движения:
ECI-положение спутника → поворот в ECEF с учётом вращения Земли → угол места над наземным
пунктом → проверка затенения Землёй для МСС-связей. Она не сверена с эталонным модулем.

**Если появятся официальные `geometry.py` и файлы сценариев** — их нужно подключить первыми
и свериться по числам (координаты спутников в конкретный момент времени, состав видимых
связей). При расхождениях в модели (например, учёт прецессии узла орбиты, другой критерий
затенения) — обновить `js/geometry.js` и/или `js/simulation.js`.

Формат JSON, который сейчас понимает загрузчик (`js/validate.js`, `handleFileUpload` в
`js/app.js`), описан примерами в `examples/`:

- `examples/example_full.json` — корректный сценарий (без ошибок валидации).
- `examples/example_broken.json` — намеренно содержит 5 разных ошибок (нет шлюза, 0 спутников
  в плоскости, отрицательная длительность, `step_seconds` строкой, `end_hour <= start_hour`) —
  чтобы заранее проверить, что сообщения об ошибках понятны и покрывают типичные случаи.

Если структура официальных файлов будет отличаться (другие имена полей, другая единица
измерения) — нужно поправить `validateScenario` и маппинг в `handleFileUpload`.

## Как подобран рекомендованный вариант (кнопка «Рекомендованный вариант»)

Базовая конфигурация по умолчанию (3 плоскости по 16 КА, RAAN 0/120/240°, без смещений,
порог угла места 10°) даёт **~77% доступности** в среднем и не достигает целевого ориентира
90% ни для одного из пяти северных пунктов. Диагностика (`tools/tune.py`) показала, что
причина не в межспутниковой сети и не в фазировании, а в **прямой видимости шлюза**
(Москва, 55.75° с.ш.): при пороге 10° над ним в среднем видно всего ~0.96 спутника
одновременно, что даёт систематические ~20% простоя, не устраняемые увеличением дальности
МСС.

Кнопка «Автоподбор конфигурации под 90%» в интерфейсе перебирает RAAN-смещение,
фазирование, дальность МСС и порог угла места (см. `autoTuneConfig` в `js/simulation.js`) и
находит конфигурацию с максимальной минимальной доступностью среди пунктов. Найденный вариант
(RAAN-смещение −20° на всех плоскостях, фазирование +7.5°, МСС 3000 км, порог угла места 5°)
даёт **~92% доступности на каждом пункте** за расчётные сутки — он и зашит в пресет
«Рекомендованный вариант». Понижение порога угла места до 5° — реалистичный, часто
используемый параметр для наземных станций LEO-группировок, а не искусственная подгонка
модели.

## Карта состояния сети

- Спутники окрашены по орбитальной плоскости; **наведите курсор** на любой спутник —
  всплывёт его номер и состояние (активен / на активном маршруте / в отказе).
- **Спутники в отказе** отображаются приглушённо с красным крестом (не исчезают) — чтобы
  было видно «аппарат и его состояние».
- Спутники **активного маршрута** подписаны и подсвечены белым кольцом.
- **Клик по спутнику** выбирает его в форме отказов (панель «Периоды недоступности»
  подсвечивается) — так закрывается сценарий проверки «выбрать спутник текущего маршрута
  и задать период его недоступности».
- Клик по наземному пункту выбирает его как активный.

## Выгрузка и повторная загрузка (round-trip)

Для каждого сохранённого варианта доступны два экспорта:

- **«Сценарий .json»** — формат файла-сценария (`ground_stations` / `planes` / …),
  который **загружается обратно** через форму. Номера плоскостей сохраняются, поэтому id
  спутников и ссылки в отказах не «едут». Это цикл «изменил проект → выгрузил → загрузил».
- **«Результаты .json»** — конфигурация во внутреннем виде + рассчитанные метрики (для
  отчёта). Такой файл тоже можно загрузить обратно — загрузчик распознаёт обёрнутый формат.

Кнопка **«Выгрузить текущий сценарий»** в панели «Расчёт» экспортирует текущую (ещё не
рассчитанную) конфигурацию — удобно для передачи проекта до расчёта.

## Сравнение вариантов

Помимо таблицы показателей доступности, сравнение показывает секцию **«Параметры
конфигурации»** с построчным сопоставлением (число спутников, плоскостей, RAAN-смещение,
фазирование, дальность МСС, порог угла места, длительность/шаг, число отказов) — строки с
различающимися значениями **подсвечены**, как требует ТЗ («видны изменённые параметры,
итоговые показатели и различия»).

## Доп. функции сверх обязательного минимума

- **Поиск наиболее уязвимых спутников** (кнопка «Найти уязвимые спутники»): перебирает по
  одному спутнику в 24-часовой отказ и ранжирует по падению средней доступности —
  `findVulnerableSatellites` в `js/simulation.js`.
- **Автоматический подбор конфигурации** (кнопка «Автоподбор конфигурации под 90%»): грубый
  перебор RAAN/фазирования/МСС/порога угла места с применением результата одним кликом —
  `autoTuneConfig` в `js/simulation.js`.

## Известные ограничения

- Расчёт полностью клиентский: сохранённые варианты не переживают перезагрузку страницы
  (кроме ручного экспорта в JSON кнопкой «Экспорт JSON»).
- Карта — полярная проекция с градусной сеткой, без контуров континентов.
- Физика орбит — невозмущённая круговая модель (без учёта прецессии, атмосферного торможения
  и т.п.), см. раздел про официальные данные выше.
