# Двухэтапный мониторинг природных пожаров по данным ДЗЗ

Решение кейса КосмоХакатона 2026: два расчётных модуля по спутниковым снимкам,
единый файл ответа в формате RLE, подсчёт метрики и информационно-аналитический
сервис с картой, векторной выгрузкой и REST API.

| Модуль | Вход | Выход |
|---|---|---|
| 1 — активное горение | AF-чип 256 × 256 @ 375 м: VIIRS I1–I5 + вспомогательные слои | бинарная маска: 1 — пиксель природного горения, 0 — всё прочее, включая техногенные термоаномалии |
| 2 — гари и степень поражения | BS-чип 512 × 512 @ 20 м: Sentinel-2 «до»/«после», Sentinel-1 «до»/«после», рельеф, тип покрова | маска 0–3: 0 — не горело, 1/2/3 — слабая, средняя, сильная степень |

## Схема пайплайна

```
AF-чип ──► валидность и день/ночь ──► кандидаты по мягкому порогу I4, I4−I5
              │                               │
              │                               ▼
              │                     контекст в окне 21×21 (фон без кандидатов)
              │                               │
              │                               ▼
              └──────────────────►  отбраковка ложных: застройка (факелы, печи),
                                     солнечный блик, вода, нагретый грунт,
                                     край облака и дымовой шлейф
                                              │
                                              ▼
                                    [обученная модель, если есть веса]
                                              │
                                              ▼
                                       бинарная маска ──┐
                                                        │
BS-чип ──► NBR(до), NBR(после), dNBR, RdNBR, dNDVI      │
              │                                         │
              ├─► пороги dNBR по типу покрова           │   RLE
              │   (USGS для леса, региональная шкала    ├─────────► submission.csv
              │    для степи, пашни и поймы)            │
              ├─► подтверждение: падение NDVI,          │
              │   наличие биомассы, строгость на пашне  │
              ├─► SCL: облака и тени исключаются,       │
              │   контур под ними восстанавливается     │
              │   по падению Sentinel-1 VH              │
              ├─► морфология: мелочь, дыры, край        │
              │                                         │
              └─► [обученная модель] ──► маска 0–3 ─────┘
                                              │
                                              ▼
                       векторизация ──► каталог сервиса ──► карта, GeoJSON, справка
```

Score = 0.35 · F1_af + 0.35 · IoU_burn + 0.30 · mIoU_sev; все компоненты —
микро-усреднение по общему пулу пикселей.

## Требования к окружению

* Python 3.11 (проверено на 3.11.15; минимально — 3.10);
* зависимости с точными версиями — `requirements.txt` (дублируются в `pyproject.toml`);
* ОС Linux или macOS; внешние сервисы и сеть для инференса не нужны;
* GPU не требуется: решение считается на CPU, обучение — градиентный бустинг по пиксельным признакам.

```bash
python -m pip install -r requirements.txt   # или: make setup
```

Альтернатива — Docker:

```bash
docker build -t firewatch .
docker run --rm -v /path/to/test:/data -v "$PWD/out:/out" firewatch \
  python inference.py --data-dir /data --output /out/submission.csv
```

## Запуск инференса

```bash
python inference.py --data-dir /path/to/test --output /path/to/submission.csv
```

Скрипт читает `sample_submission.csv` из каталога данных, обрабатывает все
перечисленные в нём чипы (включая облачные), пишет файл ответа по указанному
пути и завершается с кодом 0 без интерактивного ввода. Файл появляется ровно
там, где указано в `--output`; промежуточных артефактов не создаётся.

Полезные ключи:

| Ключ | Назначение |
|---|---|
| `--weights-dir DIR` | каталог с весами (по умолчанию `data/weights` из конфигурации) |
| `--no-model` | считать только по правилам и порогам, игнорируя веса |
| `--jobs N` | число процессов (0 — по числу ядер) |
| `--sample-submission PATH` | шаблон ответа, если он лежит вне каталога данных |
| `--config PATH` | другой YAML с параметрами |
| `--set КЛЮЧ=ЗНАЧЕНИЕ` | точечное переопределение параметра, например `--set active_fire.window=15` |

### Ожидаемая структура входных данных

```
test/
├── meta.csv                  # chip_id, kind, width, height, gsd, valid_frac, cloud_frac
├── sample_submission.csv     # chip_id, class_id, rle — задаёт состав строк ответа
├── af/
│   ├── AF_te_000001.tif      # 5 каналов: I1, I2, I3, I4, I5
│   └── AF_te_000001_aux.tif  # тип покрова, рельеф, углы, метео, маска валидности
└── bs/
    ├── BS_te_000001_pre.tif      # 10 каналов Sentinel-2: B2…B12, SCL
    ├── BS_te_000001_post.tif
    ├── BS_te_000001_s1_pre.tif   # 2 канала Sentinel-1: VV, VH
    ├── BS_te_000001_s1_post.tif
    └── BS_te_000001_aux.tif      # высота, уклон, экспозиция, тип покрова
```

Файлы ищутся рекурсивно по `chip_id`, роль определяется суффиксом имени, поэтому
раскладка по подкаталогам может быть любой. Поддерживаются `.tif`, `.npy`, `.npz`.
Если в выданном релизе суффиксы или порядок каналов отличаются, правится только
раздел `data` в `configs/default.yaml` — код менять не нужно.

## Запуск обучения

```bash
python train.py --data-dir data/train --output-dir data/weights --calibrate-thresholds
```

Обучаются два градиентных бустинга (модуль 1 — бинарный, модуль 2 —
четырёхклассовый) на тех же признаках, что считаются на инференсе. Разбиение на
обучение и валидацию — по `fire_event_id`, чтобы чипы одного пожара не попадали
в обе части. Ключ `--calibrate-thresholds` пересчитывает пороги dNBR по типам
покрова и пишет их в `configs/calibrated.yaml`; применить их можно так:

```bash
python inference.py --data-dir data/test --output submission.csv \
  --set burn_severity.thresholds.grass="{t1: 0.07, t2: 0.21, t3: 0.39}"
```

### Веса

Обученные веса (`af_model.joblib`, `bs_model.joblib`, суммарно ~1,4 МБ)
включены в репозиторий в `data/weights/`, поскольку запуск `train.py` при
проверке не обязателен, а без весов решение теряет основной прирост качества
(Score на train: 0,71 с моделью против 0,17 на чистых правилах). Они же
полностью воспроизводимы командой `train.py` из обучающей части набора —
повторный запуск с тем же `seed` даёт те же веса. **Инференс работает и без
весов** — тогда решение принимают физически обоснованные правила и пороги из
`configs/default.yaml`. Наличие весов определяется автоматически; принудительно
отключить их можно ключом `--no-model`.

## Информационно-аналитический сервис

```bash
python scripts/build_service_catalog.py --data-dir data/train --output data/service_catalog
python scripts/run_service.py --catalog data/service_catalog --port 8000
# веб-карта: http://localhost:8000/
```

Сервис работает на заранее подготовленном каталоге сцен: чипы один раз
прогоняются обоими модулями, результат векторизуется и сохраняется в GeoJSON,
после чего запрос отрабатывает за доли секунды. Чипы без геопривязки
(обезличенный тест) в каталог не попадают — их нельзя положить на карту.

| Метод | Назначение |
|---|---|
| `POST /api/query` | пространственно-временной запрос: `bbox` или `geometry` (GeoJSON), `date_from`, `date_to`, `clip`; возвращает термоточки, контуры и справку |
| `GET /api/hotspots?bbox=…&date_from=…&date_to=…` | карта термоточек за период |
| `GET /api/burn-scars?bbox=…&download=true` | контуры гарей в GeoJSON (EPSG:4326) с атрибутами `contour_id`, `severity_class`, `area_ha` |
| `GET /api/summary?bbox=…&format=csv\|json` | аналитическая справка: площадь и распределение по трём степеням |
| `GET /api/catalog`, `POST /api/catalog/reload` | состав каталога и его перечитывание |
| `GET /health` | состояние сервиса |

Пример запроса без пользовательского интерфейса:

```bash
curl -s -X POST http://localhost:8000/api/query \
  -H 'Content-Type: application/json' \
  -d '{"bbox":[36.4,45.9,37.9,46.8],"date_from":"2024-04-01","date_to":"2024-10-31"}' | head -40
```

Площадь считается по числу пикселей и размеру пикселя на местности в проекции
чипа (для 20 м — 0,04 га на пиксель), а не по площади полигона в градусах;
геометрия при этом отдаётся в EPSG:4326. При включённой обрезке (`clip`) площадь
контура, частично попавшего в запрос, уменьшается пропорционально попавшей части.

## Воспроизводимость

* Все пороги и параметры лежат в `configs/default.yaml`; абсолютных путей с машины разработчика в коде нет.
* Случайные начальные значения фиксируются (`seed` в конфигурации) в обучении и в инференсе.
* Решение детерминировано: правила и пороги не используют случайность, число процессов на результат не влияет (`tests/test_pipeline.py::test_inference_is_reproducible` сравнивает файлы, полученные в 1 и 2 процесса, побайтово). Повторный запуск даёт то же значение метрики — расхождение 0,000 при допустимых 0,005.
* Потоки BLAS/OpenMP в инференсе ограничены единицей, параллелизм идёт процессами по чипам: время предсказуемо, результат от числа потоков не зависит.

## Автотесты

```bash
python -m pytest -q     # 45 тестов
```

Тесты идут на синтетическом наборе, который повторяет структуру каталогов,
порядок каналов и формат меток выданных данных:

```bash
python scripts/make_synthetic_data.py --output data/synthetic/train --n-af 6 --n-bs 3 --split tr
```

Синтетика нужна только для проверки работоспособности кода и не является
данными соревнования; финальные веса на ней не обучаются.

## Данные и лицензии

* Данные Copernicus (Sentinel-1, Sentinel-2, Copernicus DEM) — открытая лицензия Copernicus.
* Продукты MODIS/VIIRS — общественное достояние (NASA), ESA WorldCover — CC BY 4.0.
* Библиотеки: NumPy, SciPy, pandas, scikit-learn, rasterio, Shapely, FastAPI, Uvicorn, PyYAML — открытые лицензии BSD/MIT/Apache 2.0.
* Картографическая подложка веб-карты — OpenStreetMap (ODbL), библиотека Leaflet (BSD-2) подключается с CDN; без сети карта переключается на встроенный SVG-рендер, вся остальная функциональность сохраняется.
* Предобученные внешние модели не используются. Готовые продукты активного горения и выгоревших площадей (FIRMS, VNP14, MCD64A1 и прочие) в решении не применяются.
